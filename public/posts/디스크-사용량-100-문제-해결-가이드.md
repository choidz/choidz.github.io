# 디스크 사용량 100% 문제 해결 가이드

## 증상 및 오류 메시지
디스크 사용량이 100%에 도달하면 시스템의 성능 저하와 응답 불능 상태가 발생할 수 있습니다. 이로 인해 파일 생성, 수정, 삭제 작업이 불가능해지며, 애플리케이션이 정상적으로 작동하지 않을 수 있습니다. 예를 들어, 아래와 같은 메시지가 나타날 수 있습니다.

```bash
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1       100G  100G     0 100% /
```

이 메시지는 특정 파일 시스템의 사용량이 100%에 도달했음을 나타냅니다. 이 경우, 즉시 조치를 취해야 합니다.

## 원인 분석
디스크 사용량이 100%에 도달하는 원인은 다양합니다. 일반적인 원인으로는 다음과 같은 것들이 있습니다:
1. **로그 파일 증가**: 시스템 로그 파일이 과도하게 증가하여 디스크 공간을 차지할 수 있습니다.
2. **임시 파일**: 애플리케이션에서 생성된 임시 파일이 삭제되지 않고 쌓일 수 있습니다.
3. **백업 파일**: 주기적인 백업 작업으로 인해 불필요한 파일이 쌓일 수 있습니다.
4. **대용량 파일**: 사용자에 의해 대용량 파일이 생성되어 디스크를 채울 수 있습니다.

## 확인 명령어
디스크 사용량을 확인하기 위해 다음 명령어를 사용할 수 있습니다:
```bash
df -h
```
이 명령어는 각 파일 시스템의 전체 용량, 사용량, 남은 용량 등을 보여줍니다. 또한, 특정 디렉토리의 파일 크기를 확인하려면 다음 명령어를 사용할 수 있습니다:
```bash
du -sh /path/to/directory/*
```
이 명령어는 지정한 디렉토리 내의 각 파일과 서브디렉토리의 크기를 요약하여 보여줍니다.

## 해결 절차
디스크 사용량이 100%에 도달했을 때의 해결 방법은 다음과 같습니다:
1. **불필요한 파일 삭제**: `rm` 명령어를 사용하여 불필요한 파일을 삭제합니다. 예를 들어:
   ```bash
   rm -rf /path/to/unwanted/file
   ```
2. **로그 파일 정리**: 시스템 로그 파일을 정리합니다. 예를 들어, `logrotate`를 설정하여 주기적으로 로그 파일을 압축하거나 삭제하도록 할 수 있습니다.
3. **임시 파일 정리**: `/tmp` 디렉토리 내의 임시 파일을 정리합니다. 예를 들어:
   ```bash
   rm -rf /tmp/*
   ```
4. **디스크 공간 확인 및 모니터링**: `ncdu`와 같은 도구를 사용하여 디스크 사용량을 시각적으로 확인하고, 공간을 차지하는 파일을 쉽게 찾을 수 있습니다.
   ```bash
   ncdu /
   ```

## 재발 방지 체크리스트
1. **로그 관리**: `logrotate`와 같은 도구를 사용하여 로그 파일의 크기를 관리합니다.
2. **임시 파일 관리**: 주기적으로 임시 파일을 정리하는 스크립트를 설정합니다.
3. **디스크 모니터링**: `cron`을 사용하여 주기적으로 디스크 사용량을 확인하고, 일정 수준 이상일 경우 알림을 받도록 설정합니다.
4. **정기적인 백업 및 클리닝**: 불필요한 백업 파일을 정리하고, 필요할 경우 클라우드 스토리지와 같은 대체 저장소를 사용합니다.

이와 같은 절차를 통해 디스크 사용량을 관리하고, 100%에 도달하는 상황을 예방할 수 있습니다. 시스템의 안정성을 유지하기 위해 주기적인 점검과 관리가 필요합니다.

## 실무 적용 체크리스트

- disk usage 100 percent 원인 분석을 적용하기 전에 현재 운영 환경의 기준값과 예외 상황을 먼저 정리합니다.
- 변경 전후로 확인할 지표를 정하고, 문제가 생겼을 때 되돌릴 수 있는 절차를 문서화합니다.
- 한 번에 모든 서버나 서비스에 적용하기보다 작은 범위에서 검증한 뒤 점진적으로 확대합니다.
- 담당자, 확인 시간, 장애 판단 기준을 명확히 남겨 같은 문제가 반복될 때 빠르게 대응할 수 있게 합니다.
