# Git 병합 충돌 해결하기: 증상부터 재발 방지까지

## 증상 및 오류 메시지

Git을 사용하다 보면 병합 충돌(Merge Conflict)이라는 상황을 마주할 수 있습니다. 이 경우, Git은 "충돌이 발생했습니다"라는 메시지와 함께 병합을 중단합니다. 일반적으로 다음과 같은 메시지를 확인할 수 있습니다:

```
CONFLICT (content): Merge conflict in <파일명>
```

이 메시지는 두 개 이상의 브랜치에서 동일한 파일을 동시에 수정했을 때 발생합니다. 특히 같은 줄을 수정했을 경우 Git은 어떤 변경 사항을 적용해야 할지 판단할 수 없기 때문에 충돌이 발생합니다. 이럴 때는 당황하지 말고, 단계적으로 해결해 나가야 합니다.

## 병합 충돌의 원인

병합 충돌은 주로 두 가지 원인으로 발생합니다. 첫 번째는 **동시 수정**입니다. 예를 들어, 두 명의 개발자가 같은 파일의 같은 줄을 수정한 경우입니다. 두 번째는 **브랜치 간의 변경 사항 겹침**입니다. 각기 다른 브랜치에서 수정한 후 메인 브랜치로 병합하려 할 때, 두 브랜치에서 같은 파일의 같은 부분을 수정했다면 충돌이 발생하게 됩니다.

## 충돌 확인 명령어

충돌이 발생했을 때는 다음 명령어를 통해 현재 상태를 확인할 수 있습니다:

```
git status
```

이 명령어를 실행하면 어떤 파일에서 충돌이 발생했는지 확인할 수 있습니다. 또한, 충돌 파일을 열어보면 Git이 자동으로 삽입한 충돌 표시(<<<<<<<, =======, >>>>>>>)를 확인할 수 있습니다. 이 표시를 통해 현재 브랜치의 변경 사항과 병합하려는 브랜치의 변경 사항을 비교할 수 있습니다.

## 해결 절차

1. **충돌 파일 열기**: `git status`로 확인한 충돌 파일을 텍스트 편집기에서 엽니다.

2. **충돌 마커 이해하기**: 파일 안에 있는 충돌 마커를 확인합니다. 예를 들어,

   ```
   <<<<<<< HEAD
   내 브랜치의 코드
   =======
   병합하려는 브랜치의 코드
   >>>>>>> feature/branch-name
   ```

   여기서 `HEAD`는 현재 브랜치의 내용을 의미합니다. `=======` 아래는 병합하려는 브랜치의 내용을 의미합니다.

3. **수동으로 코드 수정하기**: 충돌 마커를 기준으로 최종적으로 남길 코드를 결정하고 수정합니다. 필요하다면 두 코드를 조합하여 새로운 코드를 만들 수도 있습니다.

4. **변경 사항 스테이징하기**: 수정이 완료된 후, 다음 명령어로 Git에 충돌이 해결되었음을 알립니다:

   ```
git add <충돌 파일 이름>
   ```

5. **커밋하기**: 충돌 해결 후, 다음 명령어로 커밋을 완료합니다:

   ```
git commit -m "Fix: Merge conflict in <파일명>"
   ```

이때, 커밋 메시지는 충돌을 해결했다는 내용을 포함하는 것이 좋습니다.

## 흔한 실수

충돌 해결 시 가장 흔한 실수는 충돌 마커를 제거하지 않고 커밋하는 것입니다. 이 경우, 빌드가 깨지거나 런타임 오류가 발생할 수 있습니다. 따라서 커밋 전에 반드시 충돌 마커가 모두 제거되었는지 확인해야 합니다. 또한, `git status` 명령어를 통해 미해결 파일이 남아있지 않은지 확인하는 것이 중요합니다.

## 재발 방지 체크리스트

1. **자주 병합하기**: 작업 중인 브랜치와 메인 브랜치를 자주 병합하여 변경 사항을 동기화합니다.
2. **작은 단위로 작업하기**: 큰 기능을 한 번에 작업하기보다 작은 단위로 나누어 작업합니다.
3. **팀원과 소통하기**: 동일한 파일을 수정할 경우 사전에 팀원과 협의하여 작업을 분담합니다.
4. **코드 리뷰 활용하기**: 코드 리뷰를 통해 잠재적인 충돌을 사전에 발견할 수 있습니다.

이러한 절차와 체크리스트를 통해 Git 병합 충돌을 효과적으로 해결하고, 향후 발생 가능성을 줄일 수 있습니다. 충돌 상황에 당황하지 않고, 체계적으로 대처하는 것이 중요합니다.
