# MySQL 데드락 현상과 해결 방법

## 증상 및 에러 메시지
MySQL에서 데드락이 발생하면 `Deadlock found when trying to get lock`이라는 메시지가 나타납니다. 이 메시지는 두 개 이상의 트랜잭션이 서로의 자원을 기다리며 무한 대기에 빠졌음을 의미합니다. 이러한 상황은 데이터베이스의 성능을 저하시킬 뿐만 아니라, 사용자에게도 영향을 미칠 수 있습니다. 따라서 데드락 문제를 신속하게 해결하는 것이 중요합니다.

## 데드락의 원인
데드락은 주로 두 가지 패턴에서 발생합니다. 첫 번째는 **역순 잠금**입니다. 두 개의 트랜잭션이 서로 다른 자원을 다른 순서로 잠그려고 할 때 발생합니다. 예를 들어, 트랜잭션 A가 자원 1을 잠그고 자원 2를 기다리는 반면, 트랜잭션 B는 자원 2를 잠그고 자원 1을 기다리는 경우입니다. 두 번째는 **갭 락과 INSERT**의 조합입니다. 두 개의 트랜잭션이 동일한 범위를 조회하고 서로의 갭 락을 차지한 상태에서 INSERT를 시도할 때 발생합니다.

## 확인 명령어
데드락 발생 시, MySQL은 `SHOW ENGINE INNODB STATUS` 명령어를 통해 마지막 데드락의 정보를 제공합니다. 이 명령어를 실행하면 데드락의 원인과 관련된 트랜잭션 정보를 확인할 수 있습니다. 다음은 해당 명령어의 사용 예시입니다:
```sql
SHOW ENGINE INNODB STATUS\G
```
이 명령어의 출력에서 `LATEST DETECTED DEADLOCK` 섹션을 찾아서 어떤 트랜잭션이 어떤 자원을 기다리고 있었는지 확인할 수 있습니다.

## 해결 절차
데드락 문제를 해결하기 위해서는 다음과 같은 절차를 따릅니다:
1. **트랜잭션 재시도:** 데드락에 의해 롤백된 트랜잭션을 다시 실행합니다. 이때, 상대 트랜잭션이 완료된 상태이므로 대부분 성공적으로 실행됩니다.
2. **잠금 순서 통일:** 여러 자원을 갱신할 때는 항상 같은 순서로 잠그도록 팀 규칙을 정합니다. 예를 들어, 자원 A와 B를 갱신할 때는 항상 A를 먼저 잠그도록 합니다.
3. **트랜잭션 최소화:** 트랜잭션의 지속 시간을 줄여서 잠금이 걸리는 시간을 최소화합니다. 외부 API 호출 등을 트랜잭션 안에 두지 않는 것이 좋습니다.
4. **인덱스 활용:** WHERE 절에 인덱스를 사용하여 풀 스캔을 방지하고, 데드락 발생 확률을 줄입니다.
5. **재발 방지:** `innodb_print_all_deadlocks` 설정을 통해 모든 데드락 정보를 로그에 남겨서 패턴을 분석합니다. 이를 통해 자주 발생하는 패턴을 찾아내어 구조적으로 개선합니다.

## 흔한 실수
데드락 문제를 해결하는 과정에서 흔히 발생하는 실수는 다음과 같습니다:
- **트랜잭션을 너무 길게 유지:** 트랜잭션이 길어질수록 데드락 발생 확률이 높아집니다. 가능한 한 짧게 유지해야 합니다.
- **잠금 순서 규칙을 무시:** 팀 내에서 잠금 순서를 통일하지 않으면 역순 잠금 문제가 발생할 수 있습니다.

## 재발 방지 체크리스트
- **잠금 순서 통일:** 자원을 갱신할 때 항상 같은 순서로 잠금.
- **트랜잭션 짧게 유지:** 외부 API 호출을 트랜잭션 안에 두지 않기.
- **WHERE에 인덱스 사용:** 인덱스 없는 UPDATE는 풀 스캔을 유발하므로 주의.
- **잠금 범위 최소화:** 갭 락 경합을 줄이기 위한 조치 필요.

데드락은 데이터베이스 시스템에서 자연스럽게 발생할 수 있는 현상입니다. 따라서 이를 완전히 없애는 것은 불가능하지만, 위의 방법들을 통해 빈도를 줄이고, 발생 시 신속하게 대응할 수 있습니다. 이 글을 통해 데드락 문제를 해결하는 데 도움이 되시길 바랍니다.
