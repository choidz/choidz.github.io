# crontab이 실행되지 않는 문제와 해결 방법

## 증상 및 오류 메시지
리눅스에서 정기적으로 실행해야 하는 작업이 crontab에 등록되어 있음에도 불구하고 실행되지 않는 경우가 많습니다. 이때는 별도의 에러 메시지나 로그가 남지 않아 원인을 파악하기가 어려울 수 있습니다. 이러한 상황은 특히 스크립트가 정상적으로 실행될 때와 달리 crontab에서만 문제가 발생하는 경우에 자주 발생합니다. 사용자는 crontab에서 작업이 실행되지 않는다는 증상에 직면하게 됩니다.

## 대표적인 원인
crontab이 정상적으로 실행되지 않는 이유는 여러 가지가 있지만, 가장 흔한 원인은 다음과 같습니다.
1. **환경 변수의 부재**: crontab은 사용자가 로그인할 때 로드되는 환경 변수를 완전히 상속받지 않기 때문에, PATH와 같은 필수 환경 변수가 부족할 수 있습니다. 
2. **스크립트의 실행 권한 부족**: 스크립트 파일에 실행 권한이 없거나, 잘못된 소유권 설정으로 인해 실행되지 않을 수 있습니다. 
3. **상대 경로 사용**: 스크립트 내에서 상대 경로를 사용하면 crontab 환경에서 해당 파일을 찾지 못해 실패할 수 있습니다.

이 외에도 crontab의 설정 방식에 따라 다르게 동작할 수 있는 점도 유의해야 합니다.

## 확인 명령어
crontab이 제대로 실행되지 않는 경우, 다음과 같은 명령어로 환경 변수를 확인할 수 있습니다. 
```bash
* * * * * env > /tmp/cron_env.log 2>&1
```
이 명령어를 통해 crontab이 사용하는 환경 변수를 확인할 수 있으며, 이를 통해 문제의 원인을 진단할 수 있습니다.

## 해결 절차
1. **절대 경로 사용**: crontab에 등록할 스크립트의 경로는 항상 절대 경로로 지정해야 합니다. 예를 들어, `/home/user/script.sh`와 같이 작성해야 합니다.
2. **환경 변수 설정**: crontab의 최상단에 다음과 같이 환경 변수를 명시적으로 설정해줍니다.
```bash
SHELL=/bin/bash
PATH=/usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin
```
3. **스크립트 실행 권한 확인**: 스크립트에 실행 권한이 있는지 확인하고, 없을 경우 다음 명령어로 권한을 부여합니다.
```bash
chmod +x /path/to/script.sh
```
4. **로그 설정**: crontab 작업 뒤에 표준 출력 및 에러를 로그 파일로 리다이렉션하여 문제를 추적할 수 있도록 합니다.
```bash
* * * * * /path/to/script.sh >> /var/log/script.log 2>&1
```
이렇게 설정하면 스크립트 실행 시 발생하는 에러를 확인할 수 있습니다.

## 흔한 실수
- **상대 경로 사용**: 스크립트 내에서 상대 경로를 사용하면 crontab 환경에서 해당 파일을 찾지 못할 수 있습니다. 항상 절대 경로를 사용해야 합니다.
- **실행 권한 누락**: 스크립트에 실행 권한을 부여하지 않으면 crontab에서 실행되지 않습니다. 반드시 chmod 명령어로 실행 권한을 확인해야 합니다.
- **환경 변수 설정 누락**: crontab은 기본적으로 제한된 환경에서 실행되므로, 필요한 환경 변수를 명시적으로 설정해주어야 합니다.

## 재발 방지 체크리스트

- [ ] 스크립트에 실행 권한이 부여되었는가?
- [ ] crontab에 필요한 환경 변수가 설정되었는가?
- [ ] 로그 파일을 통해 에러를 추적할 수 있는가?

위의 체크리스트를 통해 crontab이 실행되지 않는 문제를 예방하고, 안정적인 작업 스케줄링을 유지할 수 있습니다. 문제가 발생할 경우, 이러한 절차를 통해 원인을 파악하고 해결해 나가시기 바랍니다.
