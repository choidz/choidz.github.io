# Elasticsearch에서 read_only_allow_delete 해제하는 방법

## 증상 및 오류 메시지
Elasticsearch에서 인덱스가 `read_only_allow_delete` 상태로 변경되면, 해당 인덱스에 대한 쓰기 작업이 차단됩니다. 이 상태에서는 데이터를 추가하거나 수정할 수 없고, 삭제만 가능합니다. 일반적으로 디스크 용량이 부족하거나, 클러스터의 상태가 비정상일 때 발생합니다. 이로 인해 애플리케이션에서 데이터 쓰기 작업이 실패하며, 다음과 같은 오류 메시지가 나타납니다:

```
{"error":{"root_cause":[{"type":"index_read_only_exception","reason":"index [your_index_name] is marked read-only/allow delete (api)"}],"type":"index_read_only_exception","reason":"index [your_index_name] is marked read-only/allow delete (api)"},"status":500}
```

이 오류는 인덱스가 읽기 전용으로 설정되어 있어 데이터를 추가할 수 없음을 나타냅니다.

## 원인 분석
이 문제의 주된 원인은 디스크 사용량이 너무 높아져 Elasticsearch가 자동으로 인덱스를 읽기 전용 상태로 변경하기 때문입니다. Elasticsearch는 디스크 사용량이 95%를 초과하면 인덱스를 보호하기 위해 이러한 조치를 취합니다. 이 외에도 클러스터의 상태가 불안정하거나, 인덱스 설정이 잘못되었을 경우에도 발생할 수 있습니다.

디스크 사용량을 확인하기 위해 다음 명령어를 사용할 수 있습니다:

```
GET _cat/allocation?v
```

이 명령어를 통해 각 노드의 디스크 사용량과 여유 공간을 확인할 수 있습니다.

## 해결 절차
`read_only_allow_delete` 상태를 해제하기 위해서는 다음 단계를 따르시면 됩니다:

1. **디스크 여유 공간 확보**: 먼저, 클러스터의 디스크 사용량을 확인하고, 필요하다면 불필요한 데이터를 삭제하거나, 추가 저장소를 연결하여 디스크 여유 공간을 확보합니다.

2. **인덱스 설정 변경**: 디스크 여유 공간이 확보되면, 해당 인덱스의 `read_only_allow_delete` 설정을 해제합니다. 다음 명령어를 사용하여 설정을 변경할 수 있습니다:

```
PUT /your_index_name/_settings
{
  "index": {
    "blocks": {
      "read_only_allow_delete": false
    }
  }
}
```

3. **상태 확인**: 설정 변경 후, 인덱스의 상태를 확인하여 정상적으로 변경되었는지 확인합니다. 다음 명령어를 사용하여 상태를 확인할 수 있습니다:

```
GET /your_index_name/_settings
```

4. **모니터링**: 변경 후에도 디스크 사용량을 지속적으로 모니터링하여, 같은 문제가 재발하지 않도록 관리합니다.

## 흔한 실수
1. **디스크 여유 공간 미확보**: 인덱스 설정을 변경하기 전에 디스크 여유 공간을 확보하지 않으면, 다시 읽기 전용 상태로 돌아갈 수 있습니다.
2. **인덱스 이름 오타**: 명령어를 입력할 때 인덱스 이름에 오타가 있을 경우, 설정 변경이 적용되지 않습니다. 정확한 인덱스 이름을 확인해야 합니다.
3. **클러스터 상태 무시**: 클러스터가 yellow 또는 red 상태일 때 설정을 변경하면, 문제가 해결되지 않을 수 있습니다. 클러스터 상태를 정상으로 복구한 후 설정을 변경해야 합니다.

## 재발 방지 체크리스트
- [ ] 디스크 사용량을 85% 이하로 유지하기 위한 모니터링 설정
- [ ] 정기적인 데이터 정리 및 백업 계획 수립
- [ ] 클러스터의 노드 수 및 리소스 확장 계획
- [ ] 인덱스 설정 변경 시 클러스터 상태 점검

이와 같은 절차를 통해 Elasticsearch의 `read_only_allow_delete` 상태를 해제하고, 재발 방지를 위한 조치를 취할 수 있습니다. 이를 통해 안정적인 데이터 관리를 유지할 수 있습니다.
