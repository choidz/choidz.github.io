# 데이터베이스 커넥션 풀 고갈 문제 해결하기

## 증상 및 오류 메시지
데이터베이스 커넥션 풀 고갈 현상은 애플리케이션에서 데이터베이스에 연결을 요청했을 때, 커넥션을 얻지 못하고 대기하게 되는 상황을 말합니다. 이때 발생하는 대표적인 오류 메시지는 다음과 같습니다.

```
java.sql.SQLTransientConnectionException: HikariPool-1 - Connection is not available, request timed out after 30000ms.
```

이 오류는 커넥션 풀이 고갈되어 더 이상 사용할 수 있는 커넥션이 없음을 의미합니다. 사용자는 API 호출이 지연되거나 실패하는 경험을 하게 되며, 이는 서비스의 신뢰성에 큰 영향을 미칠 수 있습니다.

## 원인 분석
커넥션 풀 고갈의 원인은 다양합니다. 가장 일반적인 원인은 다음과 같습니다.

1. **트랜잭션이 길어질 때**: 데이터베이스 트랜잭션 내에서 외부 API 호출이나 대기 시간이 긴 쿼리가 포함되면, 커넥션이 오랜 시간 점유됩니다. 이로 인해 다른 요청이 대기하게 되어 커넥션 풀이 고갈됩니다.

2. **스레드 기아 데드락**: 특정 로직에서 여러 커넥션을 필요로 하는 경우, 모든 스레드가 서로의 커넥션을 기다리게 되어 데드락이 발생할 수 있습니다.

3. **느린 쿼리**: 인덱스 누락이나 비효율적인 쿼리로 인해 커넥션 점유 시간이 늘어나면, 요청 처리 속도가 떨어지고 커넥션 풀이 고갈됩니다.

## 확인 명령어 및 로그
커넥션 풀의 상태를 확인하기 위해 다음과 같은 명령어를 사용할 수 있습니다. HikariCP의 설정을 로그로 남기는 방법도 유용합니다.

```yaml
logging:
  level:
    com.zaxxer.hikari.HikariConfig: DEBUG
    com.zaxxer.hikari: TRACE
```

이 설정을 통해 커넥션 풀의 상태를 실시간으로 모니터링할 수 있습니다. 예를 들어, 다음과 같은 로그를 통해 현재 커넥션의 사용 상태를 확인할 수 있습니다.

```
[HikariPool-1 - Pool stats (total=15, active=10, idle=5, waiting=0)]
```

## 해결 절차
커넥션 풀 고갈 문제를 해결하기 위해서는 다음과 같은 절차를 따르는 것이 좋습니다.

1. **트랜잭션 범위 최소화**: DB 연결이 필요 없는 로직은 @Transactional 범위에서 제외해야 합니다. 외부 API 호출은 별도의 트랜잭션으로 처리하는 것이 좋습니다.

2. **풀 사이즈 조정**: HikariCP의 `maximumPoolSize`를 적절히 설정하여 커넥션 풀이 고갈되지 않도록 해야 합니다. 일반적으로는 CPU 코어 수에 비례하여 설정하는 것이 좋습니다.

   ```yaml
   spring:
     datasource:
       hikari:
         maximum-pool-size: 15
         connection-timeout: 30000
   ```

3. **느린 쿼리 최적화**: 쿼리 성능을 분석하여 인덱스를 추가하거나, 비효율적인 쿼리를 수정하여 커넥션 점유 시간을 줄여야 합니다.

## 흔한 실수
커넥션 풀 고갈 문제를 해결하는 과정에서 흔히 발생하는 실수는 다음과 같습니다.

- **풀 사이즈를 무작정 늘리기**: 커넥션 풀 사이즈를 무작정 늘리는 것은 오히려 DB 서버에 부하를 줄 수 있습니다. 적절한 사이즈를 설정하는 것이 중요합니다.

## 재발 방지 체크리스트
커넥션 풀 고갈 문제를 예방하기 위해 다음과 같은 체크리스트를 활용해 보세요.

- [ ] 트랜잭션 범위를 최소화했는가?
- [ ] 커넥션 풀 사이즈가 적절하게 설정되었는가?
- [ ] 느린 쿼리가 최적화되었는가?
- [ ] 커넥션 점유 시간을 모니터링하고 있는가?

이와 같은 절차와 체크리스트를 통해 커넥션 풀 고갈 문제를 효과적으로 해결하고 예방할 수 있습니다. 실무에서 발생할 수 있는 다양한 상황을 고려하여 적절한 조치를 취하는 것이 중요합니다.
