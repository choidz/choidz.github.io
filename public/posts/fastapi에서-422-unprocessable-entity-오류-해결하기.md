# FastAPI에서 422 Unprocessable Entity 오류 해결하기

## 오류 증상
FastAPI를 사용하여 API를 개발할 때, 클라이언트에서 요청을 보냈음에도 불구하고 422 Unprocessable Entity 오류가 발생하는 경우가 있습니다. 이 오류는 주로 클라이언트에서 전송한 데이터가 서버에서 처리할 수 없는 형식일 때 발생합니다. 예를 들어, 클라이언트가 JSON 형식으로 데이터를 보내는데, FastAPI가 기대하는 데이터 형식과 일치하지 않을 때 이 오류가 발생합니다. 이러한 상황은 특히 요청 본문에 포함된 데이터의 타입이나 필수 필드가 누락된 경우에 자주 발생합니다.

## 원인 분석
422 Unprocessable Entity 오류의 가장 일반적인 원인은 클라이언트와 서버 간의 데이터 불일치입니다. FastAPI는 Pydantic 모델을 사용하여 요청 본문의 데이터를 검증합니다. 만약 클라이언트가 잘못된 데이터 형식으로 요청을 보낸다면, FastAPI는 이를 처리할 수 없고 오류를 반환합니다. 예를 들어, 문자열이 필요한 필드에 숫자나 null 값을 보내는 경우가 이에 해당합니다. 또한, 필수 필드가 누락되었거나, 데이터 타입이 잘못된 경우에도 이 오류가 발생할 수 있습니다.

## 확인 명령어
이 오류를 해결하기 위해서는 먼저 클라이언트에서 보내는 요청의 내용을 확인해야 합니다. 다음과 같은 명령어를 사용하여 클라이언트에서 보내는 데이터의 형식을 출력할 수 있습니다.

```javascript
console.log(typeof this.form.title);
console.log(typeof this.form.keyword);
console.log(typeof this.form.writer);
console.log(typeof this.form.char);
```

이 명령어를 통해 각 필드의 데이터 타입을 확인하고, 서버에서 기대하는 타입과 일치하는지 점검할 수 있습니다. 또한, FastAPI의 로그를 통해 어떤 데이터가 수신되었는지 확인하는 것도 중요합니다.

## 해결 절차
1. **클라이언트 데이터 검증**: 클라이언트에서 보내는 데이터가 FastAPI에서 정의한 모델과 일치하는지 확인합니다. 예를 들어, FastAPI에서 다음과 같은 모델을 정의했을 경우:

   ```python
   from pydantic import BaseModel

   class Review(BaseModel):
       title: str
       words: str
       writer: str = None
       char: int = None
   ```

   클라이언트에서 보내는 데이터는 다음과 같이 되어야 합니다:
   ```json
   {
       "title": "Sample Title",
       "words": "Sample Keyword",
       "writer": "Author Name",
       "char": 100
   }
   ```

2. **API 요청 수정**: 클라이언트에서 잘못된 필드명을 사용하고 있거나 데이터 타입이 잘못되었을 경우, 이를 수정합니다. 예를 들어, `keyword`라는 필드명을 `words`로 변경해야 할 수 있습니다.

3. **서버 로그 확인**: FastAPI 서버의 로그를 확인하여 어떤 데이터가 수신되었는지, 어떤 오류가 발생했는지 확인합니다. 이를 통해 문제를 보다 쉽게 파악할 수 있습니다.

4. **테스트 요청 보내기**: 수정된 클라이언트 코드로 다시 요청을 보내고, 오류가 해결되었는지 확인합니다.

## 흔한 실수
많은 개발자들이 클라이언트에서 보내는 데이터의 형식이나 필드명을 잘못 설정하여 422 오류를 경험합니다. 특히, JSON 형식의 데이터에서 필드명을 잘못 작성하거나, 필수 필드를 누락하는 경우가 많습니다. 또한, 데이터 타입을 잘못 설정하는 경우도 자주 발생합니다. 따라서, 클라이언트와 서버 간의 데이터 계약을 명확히 하고, 이를 문서화하는 것이 중요합니다.

## 재발 방지 체크리스트
- [ ] 클라이언트와 서버 간의 데이터 계약을 문서화하였는가?
- [ ] 요청 본문에 필요한 모든 필드가 포함되어 있는가?
- [ ] 각 필드의 데이터 타입이 서버에서 기대하는 타입과 일치하는가?
- [ ] FastAPI의 Pydantic 모델을 사용하여 데이터 검증을 충분히 하고 있는가?

이러한 점들을 체크리스트로 만들어 두면, 422 오류를 예방하는 데 큰 도움이 될 것입니다. FastAPI를 사용하여 API를 개발할 때는 항상 데이터 검증을 철저히 하고, 클라이언트와의 데이터 계약을 명확히 하는 것이 중요합니다.
